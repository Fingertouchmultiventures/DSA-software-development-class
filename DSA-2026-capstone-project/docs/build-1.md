# Build 1: Domain core in the terminal

## Goal

Build and run the first JavaScript version of the ticket-booking domain. It
models events, ticket tiers, bookings, available seats, booking references, and
a first-in-first-out waitlist. The data is held in memory: this build has no
web server or database.

The entry point also demonstrates ES-module imports and exports, greeting
functions, a `Map` of sample bookings, and a counter class.

## What this build delivers

- Event and ticket-tier creation with input validation.
- Bookings for 1 to 10 tickets, with a capacity check that rejects a booking
  when there are not enough seats.
- Cancellation that releases seats and rejects invalid repeated cancellation.
- Booking lookup by reference using a `Map`.
- A linked-list queue for first-in-first-out waitlist entries.
- A terminal demo of selling out, joining the waitlist, cancelling, and
  offering available seats to the next person in line.
- A benchmark comparing `Array.find` and `Map.get`.

## What you practise

ES modules, functions, objects, classes, `Map`, queues, input validation,
domain errors, Node.js scripts, and Big O lookup costs.

## Requirements

- Node.js 22.13 or newer
- No third-party packages

`package.json` sets `"type": "module"`. Keep using `import` and `export` in the
project's `.js` files, include `.js` in relative imports, and match named
imports to named exports and default imports to default exports.

## Run and verify

From the project directory:

```powershell
node index.js
npm run demo
npm run benchmark
```

No `npm install` is required. The benchmark's exact timings and the booking
references generated by the demo vary between runs.

### Done when

- `node index.js` prints the greeting, farewell, sample booking, and counter
  values (`0`, then `1`).
- `npm run demo` shows a booking refused with `SOLD_OUT`, people joining the
  waitlist, a cancellation returning seats, and the next eligible person being
  offered seats.
- `npm run benchmark` prints timings for both `Array.find` and `Map.get`.

## Project map

| Path | Responsibility |
| --- | --- |
| `index.js` | Entry point for the greeting, sample booking, and counter examples |
| `greetings.js` | Named `greet` and `farewell` functions |
| `object.js` | In-memory sample bookings and the `addBooking` function |
| `class.js` | Counter class with an `increment()` method and `value` getter |
| `src/domain/errors.js` | `DomainError` with a machine-readable error code |
| `src/domain/ids.js` | UUID generation and readable booking references |
| `src/domain/inventory.js` | Events, tiers, bookings, seat counts, and waitlist operations |
| `src/domain/waitlistQueue.js` | Linked-list FIFO queue |
| `scripts/demo.js` | Ticket-inventory walkthrough |
| `scripts/benchmark-lookup.js` | Array and Map lookup comparison |

## Implementation notes

During implementation, the entry point was updated to match the project's
module format and actual exports. The counter is defined in `class.js`, so it
must be imported from that file and instantiated with `new Counter()` before
its value or methods are used. The sample booking map is a default export;
`greet` and `farewell` are named exports.
